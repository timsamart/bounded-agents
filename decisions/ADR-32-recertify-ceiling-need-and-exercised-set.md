# ADR-32. Recertify ceiling, need, and exercised set {#adr-32}

**Status:** Accepted (edition 0.2.0 draft)  
**Date:** 2026-08-01  
**Deciders:** Lead author (Timotheos Samartzidis)  
**Argued in:** `chapters/3.5-decay.md`

**In plain terms:** Each quarter, recertify what was allowed and compare it to what was actually used.

## Context

Static entitlement lists alone rot into fiction. Over-declaration becomes permanent authority.

## Decision

Recertify tier ceiling and declared need together with the platform's exercised-set report.

## Why not the alternative

**Rejected:** Recertify only static entitlements and ignore what ran.

Intersection becomes a constant nobody revisits.

## What changes if you follow this

Data owners see unused reach and can shrink need. Platform must produce the exercised set from evidence.

## Cost

Quarterly ceremony time - funded from ADR-27's calendar.

## Reopen when

An auditor rejects exercised-set recertification and requires another form.
